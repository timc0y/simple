# Simple

## Reality

- Tim maintains and uses this portable agent skill. External installed users are not established by the repository.
- Supported hosts are OpenCode, Claude Code, Codex and Antigravity only. Gemini CLI support is retired by explicit owner direction; historical research and evidence are retained.
- Public contracts are the shared skill, references, commands, profiles, supported plugin manifests and hooks. Preserve published entry points except the explicitly retired Gemini extension.
- There is no application runtime or persistent production data. Local guidance can still misdirect an agent, so do not invent users, obligations, deletion permission or verification results.
- PR watching, another task queue and a universal app framework are not requirements.

## Preserve

- One shared method with progressive disclosure, not four instruction copies.
- Repository facts, real compatibility, recovery obligations and independent proof.
- User scope and authority across corrections, interruptions and handoffs.
- Raw evaluation evidence, negative results, source provenance and licences.
- Unknown host delivery and model adherence remain unknown, not assumed from local file existence.

## Current boundary

- Claude Code and Codex share `hooks/hooks.json` and `scripts/hook.mjs`. Session sources include startup, resume, clear, compact and fork. Codex requires local review/trust for changed hooks.
- The published OpenCode V1 factory remains at `.opencode/plugins/simple.mjs`. V2 uses the separate directory `integrations/opencode-v2`; it resolves each session's location, not the plugin instance's directory.
- Antigravity uses the root `plugin.json` for the shared skill. Optional PreInvocation context is generated by the installed skill's `scripts/antigravity.mjs`; it does not overwrite user hook configuration.
- Antigravity's `.gemini/config` and `.gemini/antigravity-cli` paths are its native paths, not a promise to support Gemini CLI. Multiple unresolved workspace roots receive a diagnostic rather than a guessed profile.
- All adapters use the canonical assembler inside `skills/simple/scripts/context.mjs`. The root script is a compatibility re-export; skill-only diagnostics need no checkout files.
- Context is bounded and source failures are independent. Diagnostics identify exact raw source bytes and the installed skill/assembler files, not every reference or a model's internal state.
- The optional name marker defaults off, preserves exact-format exceptions and never establishes correctness. No Stop hook reopens a completed task, and no hook grants permissions.
- Action and writing reminders are advisory; a reminder arriving after a tool result cannot change the submitted action. Native permissions and applicable conversation authority still apply.
- Automated host-contract tests exercise adapters and payloads. They are not proof of live model compaction survival or natural skill activation. `docs/hosts.md` owns installation details and evidence boundaries.

## Ordinary paths

- `skills/simple/SKILL.md` and its specialist references own the method. Commands and manifests only expose that source.
- `README.md` owns first-use guidance; `docs/hosts.md` owns host-specific configuration and verification. `AGENTS.md` owns this repository's read order, owners and authority.
- `scripts/link-skill.mjs` preflights six local links for the four supported hosts and shared skill discovery. Real files/directories are never replaced. It does not update plugin caches or authorize hooks.
- `simple.mjs init` scaffolds routes and an incomplete profile. `setup` remains an alias. `check` validates structure; `check --context` adds source identities without printing operator contents.
- `audit`, `board`, `research`, `work`, `reconcile`, `plan`, `review`, `write`, `round` and `emulate` are judgement entry points, not a compulsory sequence. `simple/round.md` and other temporary artifacts end when their evidence has a durable owner.
- The lead owns synthesis and final verification. Subagents are bounded and read-only unless assigned exclusive paths; one writer owns each file.
- `evals/README.md` owns evaluation protocol; each result directory retains raw evidence; `evals/results/README.md` owns decisions. Frozen historical runners are not automatically current host contracts.
- `upstream/` archives and `research/` are inactive reference material. Adapt useful techniques in existing owners instead of installing another workflow stack.

## Proof

- `npm test` exercises deterministic repository, context, installer and host-contract tests.
- `node skills/simple/scripts/simple.mjs check --context` validates this profile and local emission.
- `npm run test:behavior`, `npm run test:preservation`, and `npm run test:workflow` exercise fixture verifiers, not models.
- `git diff --check` checks patch whitespace.
- CI runs the full tests on Linux, selected hook/profile tests on Windows and a Claude plugin installation probe. Do not describe the Windows subset as the full suite.
- Model claims require matched evaluations and actual host/version identities. No new general improvement claim follows from these structural checks.

## Reconsider when

- Add another host only after explicit owner direction, not because a discovery tool lists it.
- Change a host adapter when a documented contract or reproduced native failure requires it.
- Add instruction text only when it expresses a needed decision and preserves existing obligations; measure any claimed gain.
- Add profile layering only for an observed nested-profile need with a tested merge rule.
- Keep the ordinary skill route until every supported host demonstrates reliable native delivery.
- Add a runtime or persistent state only when an existing owner cannot satisfy a concrete requirement.
