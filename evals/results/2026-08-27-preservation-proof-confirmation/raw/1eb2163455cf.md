Ship the one-shot CLI with its direct command path. Do not ship the daemon or bundling yet.

First establish a cold-start latency breakdown across repeated runs: process creation, module loading, command setup, remote operation, and exit. Confirm the generator→compiler import chain is present on the affected commands, and verify that the generated JSON is current and sufficient on its own. Measure bundling separately only if that path remains material afterward.

Test one small change first: have the common module read or reference the generated JSON directly, using the needed path constant without importing the generator. Preserve the command grammar, results, safety checks, and completed task records. Compare cold command latency and behavior before and after.

If it succeeds, remove the resident-service prototype and its HTTP server, installation support, second composition root, duplicate routes, parity tests, status/recovery commands, and lazy route loader. They exist only to compensate for an unproven startup cost.

A resident process becomes justified only when measurement identifies a user-needed capability that requires continuity across commands, cannot be represented as durable data, and cannot be met by the ordinary one-process command path. Faster startup alone is not that condition.
