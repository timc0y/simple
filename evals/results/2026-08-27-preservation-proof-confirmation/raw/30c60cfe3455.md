Ship the one-shot CLI, not the daemon.

First establish a cold-start latency breakdown: CLI bootstrap, module loading, generator/compiler loading, generated-JSON read, remote operation, and exit. Confirm the command’s results and command grammar are unchanged, and measure bundling separately before treating it as a solution.

Test one small change first: make the common module refer directly to the generated JSON (or its static path) without importing the generator or compiler. The command already consumes that JSON; the generator is not on its ordinary execution path.

If this removes the regression, remove the daemon, HTTP server, service installation, duplicate composition root and route table, parity tests, status/recovery commands, and lazy route loader. Keep the single CLI path and durable completed-task records.

A resident process becomes justified only when measurement identifies a required capability that must continue across commands and cannot be represented as durable data. Startup latency alone is not that condition.
