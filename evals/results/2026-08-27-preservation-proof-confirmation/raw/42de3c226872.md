Ship the one-shot CLI with the generator/compiler removed from its startup path. Do not ship the daemon or bundle yet.

First establish:

- Cold-process latency split into startup/import, generated-JSON read, remote operation, and exit.
- Whether the generator import chain accounts for the ~180 ms regression.
- Command grammar, results, safety checks, and completed-task records remain unchanged.

Test the smallest change first: make the common module obtain the generated JSON path without importing the generator—put the path constant in a dependency-free location or construct it from the existing package path. The command should read the already-generated JSON directly.

If this restores acceptable cold latency, remove the daemon, HTTP server, service installation, second composition root, duplicate route table, lazy loader, parity tests, and service status/recovery commands. Measure bundling only if the import-path change leaves a material startup cost.

A resident process becomes justified only when measurement shows a required capability needs continuity across commands and that continuity cannot be represented as durable completed-task data. Startup speed alone is not that condition.
