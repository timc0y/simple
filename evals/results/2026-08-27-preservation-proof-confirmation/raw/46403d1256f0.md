Ship the direct CLI. The daemon adds substantial machinery for an unproven 180 ms problem, while the repository facts show one local operator, one-shot commands, and no need for cross-command continuity.

Establish:

- Cold-start latency before and after the change, separately from remote-operation time.
- Import timing and the dependency chain showing `common module → generator → compiler`.
- That the command only needs the generated JSON and does not require generator or compiler behavior at runtime.
- Existing command results, safety checks, and durable task-record readability.

Test first: remove the runtime generator import and obtain the generated JSON path through the smallest local constant or standard-library path expression. Measure cold latency and run the existing behavior checks.

If this succeeds, remove the daemon’s HTTP server, service installation, second composition root, duplicate route table, parity tests, service status/recovery commands, and lazy route loader. Keep the generator if it remains part of the build or generation workflow; only its runtime import should disappear.

A resident process becomes justified only when measurement shows that startup remains materially harmful after simpler fixes and a required capability needs live continuity across commands—such as a warm authenticated session, connection, or in-memory state—that cannot be represented as durable data.
