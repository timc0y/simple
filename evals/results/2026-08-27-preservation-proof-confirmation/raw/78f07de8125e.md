Ship the direct CLI. Do not ship the daemon yet.

The evidence to establish:

- Measure cold-start latency before and after the change, separating process startup, imports, local work, and the remote operation.
- Confirm whether importing the generator/compiler is responsible for the 180 ms regression.
- Verify that the generated JSON is present, current, and readable directly by the command.
- Run existing behavior and safety checks, including durable task-record readability.
- Measure bundling only if the direct import change is insufficient.

Test the smallest change first: stop importing the generator merely to obtain the path. Point the common module directly at the generated JSON using the existing path/loading mechanism. Keep the generator and compiler only where generation actually occurs.

If latency and behavior return to the expected baseline, remove the daemon and its supporting machinery: the HTTP server, service installation, second composition root, duplicate routes, parity tests, lazy route loader, status commands, and recovery commands. The generator/compiler may remain as build-time tooling if something still generates the artifact.

A resident process becomes justified only when measurements show a requirement for continuity across commands—such as shared live state, a session, or a warm connection—that cannot be represented as durable data, and the performance benefit exceeds the operational cost of installation, recovery, and service ownership.
