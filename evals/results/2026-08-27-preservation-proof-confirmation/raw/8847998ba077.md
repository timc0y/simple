Ship the existing one-shot CLI. Do not ship the daemon for a measured startup regression that may be an accidental import chain.

### Evidence to establish

- Measure cold-start latency before and after the dependency change, separating process startup, module loading, command work, and remote-operation time.
- Confirm with an import trace or dependency graph that the path is:

  `common module → generator → compiler`

- Confirm the generated JSON is present, current, and sufficient for the command.
- Run the existing command and safety checks against representative inputs, including failure cases.
- Verify the generated artifact remains fresh through the repository’s normal generation/build path.
- Do not treat bundling as a solution until it has been benchmarked against the direct import change.

### Smallest change to test first

Change the common module to consume the generated JSON directly, or obtain only its required path through a local standard-library operation. Remove the generator and compiler from the command’s runtime import path.

Compare cold latency and command behaviour with the current CLI. The existing CLI remains the owner and composition root.

### What becomes removable

If the startup improvement is sufficient and behaviour is unchanged, remove the unshipped daemon machinery:

- HTTP server and service installation
- daemon composition root
- duplicate route table
- lazy route loader
- daemon/direct parity tests
- service status and recovery commands
- daemon-specific configuration and documentation

Retain the direct CLI route table, its tests, and durable completed task records.

### When residency becomes justified

Reconsider a resident process only when measured requirements show that repeated commands need continuity across invocations—such as retained connections, in-memory state, subscriptions, or batching—and that requirement cannot be represented safely as durable data.

A daemon would then need a concrete latency or capability target, evidence that the optimized one-shot path cannot meet it, and an operational recovery model whose cost is justified by that target.
