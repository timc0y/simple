Do not ship the resident daemon.

Establish a cold-start profile that separates process startup, module loading, generated-JSON access, remote operation, and exit. Confirm that the generator→compiler import is responsible for the roughly 180 ms regression, and verify the generated JSON’s production/update contract. Measure bundling separately before treating it as an option.

First, change the common module to obtain the generated JSON directly, without importing the generator or compiler merely to discover its path. Compare cold command latency and command results before and after.

If that removes the regression, delete the daemon prototype and its HTTP server, service installation, second composition root, duplicate route table, lazy route loader, parity tests, and service status/recovery commands. Preserve the existing one-shot command grammar, safety checks, and durable completed-task records.

A resident process becomes justified only if measurement identifies a required capability that must continue across commands and cannot be represented as durable data. Startup time alone is not that capability.
