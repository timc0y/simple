Ship the direct CLI with the generator/compiler removed from its runtime import path. Do not ship the resident daemon or bundling yet.

First establish a cold-start profile across representative commands: process startup, module loading, generator/compiler initialization, JSON read/parse, remote operation, and exit. Measure p50/p95 over repeated fresh processes, and confirm that the 180 ms is both real and material to the operator.

Test one local change first: have the common module consume the generated JSON directly, with the generator remaining a build-time concern. Verify the JSON contract and compare cold-command timings before and after. Measure bundling separately only if that change does not account for the delay.

If it succeeds, remove the daemon, HTTP server, service installation, second composition root, duplicate route table, lazy route loader, parity tests, and service status/recovery commands. The CLI remains the sole command path and owner.

A resident process is justified only if measured direct CLI performance still fails an agreed operator need after unnecessary startup work is removed, and a sustained workload can demonstrably benefit from retained process state or connections enough to outweigh its service lifecycle, recovery, and parity obligations.
