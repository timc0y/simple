Do not ship the daemon. The current evidence supports a startup/import regression, not a need for process residency.

### Evidence to establish

- Measure cold-start latency before and after the change, separating import time from the remote operation.
- Confirm the generator imports the compiler and that the command only consumes the generated JSON.
- Verify command grammar, results, safety checks, and durable task records remain unchanged.
- Measure bundling only if the direct data change does not recover the regression.

### Smallest change to test

Change the common module to reference or load the generated JSON directly. Remove the generator import from the command’s startup path. Keep the existing CLI composition root and execution path.

If latency and behaviour improve, remove the daemon prototype and its supporting machinery:

- HTTP server and service installation
- second composition root
- duplicate route table
- lazy route loader
- parity tests for the duplicate path
- service status and recovery commands

### When residency is justified

Introduce a resident process only when measurement shows that startup remains material after simplifying imports, and a required capability needs continuity across commands—such as live session state, watching, or a cache that cannot be represented as durable data. The benefit must justify the daemon’s additional installation, recovery, and operational burden.
