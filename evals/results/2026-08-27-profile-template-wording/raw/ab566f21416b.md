- Stage and users: This is a production service. Published API clients use it.
- Operators: Unknown.

- Scale and failure consequences: Unknown.

## Current boundary

- The production service must support published clients and retained customer data.
- During the bounded transition, `CustomerSerializer` accepts either customer field name, rejects conflicting values, and emits both names from one internal value.
- No other users, operators, scale, failure, security, or compatibility facts are known.

## Ordinary paths

- Use the existing migration runner for schema changes.
- Use `CustomerSerializer` for request parsing and response serialization.
- Use its existing deprecation-alias facility for the bounded field-name transition; it supplies one internal value and supports both API representations.

## Proof

- Verify retained customer data, both API representations, rollback, and removal.

- Exact verification commands are unknown.

## Reconsider when
