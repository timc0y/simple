Set the existing bundler’s production entry-point budget to 250 KB gzip and make the build fail when the checkout entry exceeds it.

Then remove the editor import from checkout’s initial path. Since checkout never opens it, the import has no present product obligation. If another flow needs the editor, load it only at that flow’s boundary.

The proposed 300-line and cyclomatic-complexity limits are unrelated: a 140-line file can still produce a 310 KB entry by importing a large dependency. They would add maintenance noise without protecting the stated budget.

Proof:

- The production build must report checkout at or below 250 KB gzip.
- The build must fail above 250 KB gzip.
- A dependency or bundle report must show the editor is absent from the initial checkout entry.
- Confirm the editor still works wherever it remains supported.
- Recheck a representative mobile session against the agreed load target.
