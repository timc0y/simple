Ship the direct one-shot CLI, after testing the import correction. Do not ship the daemon to hide an unattributed 180 ms.

Establish:

- Cold-start timings split into process startup, module loading, compilation, remote operation, and exit.
- An import/dependency trace proving that the common module pulls in the generator and compiler only to obtain a path or generated artifact.
- That the generated JSON is current, available at runtime, and can be consumed directly without changing command results or safety checks.
- Repeated cold-run benchmarks and behavior tests before and after the change. Measure bundling separately; do not assume it helps.

The smallest experiment is to replace the runtime generator import with a direct import of the generated JSON, or with a small dependency-free module containing the required path constant. Keep generation in the build step if it is still needed. Compare cold latency and command behavior.

If that succeeds, remove the runtime generator/compiler dependency from the CLI path. The daemon prototype and its supporting machinery then have no justified problem to solve: remove the HTTP server, service installation, second composition root, duplicate routes, lazy route loader, parity tests, status/recovery commands, and related operational documentation. Retain only any generator required to produce artifacts.

A resident process becomes justified only when measurements show a present requirement for continuity across commands—such as indispensable persistent connections, session state, or a cache—and that requirement cannot be represented by the existing durable task records. A 180 ms startup cost alone is not sufficient; the measured benefit must outweigh the daemon’s operational and recovery complexity.
