Ship the one-shot CLI. Do not ship the daemon.

Establish this evidence first:

- Profile cold-start time separately from the remote operation.
- Trace the import graph and confirm the generator → compiler chain is responsible for most of the ~180 ms.
- Confirm the generated JSON is already a valid, available runtime artifact and that no runtime generation is required.
- Compare command latency and results before and after the dependency change across repeated cold runs.

Test the smallest change first: have the common module reference the existing generated JSON—or derive its path with a direct local constant—instead of importing the generator. Do not bundle yet; measure the simpler fix first.

If that restores acceptable startup time, remove the displaced machinery:

- the daemon and HTTP server;
- service installation, status, and recovery commands;
- the second composition root;
- the duplicate route table;
- the lazy route loader;
- daemon/direct-CLI parity tests that only protect the deleted path.

Retain the one command surface, safety checks, remote behavior, and durable task records.

A resident process becomes justified only when a measured requirement needs continuity across commands—such as live session state, a persistent connection, or an in-memory capability that cannot be represented as durable data—and the one-shot path cannot meet that requirement after local startup costs are fixed.
