## Decision

Add the customer import as a daily job in the existing in-process runner. The runner remains the sole owner of scheduling and transient-failure retries; do not add a queue, worker, or second execution path.

The job should:

- register on the runner’s existing daily scheduling mechanism;
- execute the import through the application’s normal customer write path;
- use a durable idempotency key for the import unit (for example, source customer ID plus source version, or a dated snapshot identity) so retries and repeated schedules do not create duplicate customers;
- classify only transient import failures for the runner to retry; validation and malformed source data remain terminal failures with actionable reporting.

The workspace contains only the request, not application code or runner configuration, so the exact registration point, schedule time, retry policy, and source identity must be taken from the existing runner and import interfaces when implemented. Do not invent parallel policy.

## Proof

Prove the feature through the runner’s public surface, not by invoking the import handler directly:

1. Scheduling: advance the runner’s controllable clock to the configured daily boundary and assert that it enqueues/runs exactly one customer-import job.
2. Execution: provide a representative source fixture, run the scheduled job, and assert customers are written through the normal persistence path.
3. Retry: make the source fail transiently for the first attempt and succeed afterward; assert the runner applies its existing retry delay/count and the eventual import succeeds. Also verify a permanent invalid-input failure is not retried.
4. Idempotency: run the same scheduled work twice, including a retry-after-write scenario, and assert the resulting customer records and side effects occur once per idempotency key.

Reconsider a separate execution system only when measured runner saturation, missed scheduling deadlines, retry backlog, or required process isolation exceeds the in-process runner’s demonstrated capacity.
