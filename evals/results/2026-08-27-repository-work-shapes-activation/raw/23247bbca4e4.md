Build only the first vertical slice:

- `rookery.mjs`
  - Register `GET /pulse` with `registerRookery`.
  - Use one direct handler that returns the literal text `rook-17`.
  - Keep the handler and registration in the same file.

No framework, dependency injection, controller/service layers, configuration loader, plugin registry, package manifest, build step, deployment files, or CI are justified. There is one route, one operator, no retained data, and the host already supplies the extension point.

The smallest shape is conceptually:

```js
registerRookery("GET", "/pulse", () => "rook-17");
```

The exact handler return form should follow the host’s undocumented response convention if it differs from this assumption.

Prove it at two levels:

1. Load `rookery.mjs` in a tiny test harness that defines `globalThis.registerRookery`, captures the registration, and asserts:
   - method is `GET`;
   - path is `/pulse`;
   - invoking the handler produces exactly `rook-17`.

2. If the host runner is available, make one black-box `GET /pulse` request and assert the response body is exactly `rook-17`.

A test harness may be added as a single standalone test file using Node’s built-in facilities, but even that is optional if the host itself can perform the black-box check. The production deliverable remains one file. Reconsider additional machinery only when a second route, shared policy, configuration, persistent state, another consumer, or a real deployment requirement appears.
