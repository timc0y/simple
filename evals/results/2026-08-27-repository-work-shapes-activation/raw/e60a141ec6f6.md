Ship the one-shot CLI, not the daemon.

First establish a cold-start latency profile: wall time and import trace before remote work, comparing the current command with a build that bypasses the generator. Confirm the generated JSON’s path and contents remain correct, and measure bundling separately rather than treating it as an explanation.

Test the smallest change first: make the command read the already-generated JSON through a dependency-free path constant (or local literal/configuration), so runtime no longer imports the generator or compiler. Keep generation in the build/generation path only.

If cold latency returns to the prior range with unchanged command results, remove the daemon prototype and everything supporting its second execution path: HTTP server, service installation, duplicate composition root and routes, lazy route loader, parity suite, and service status/recovery commands.

A resident process is justified only if measurement shows a required capability needs live continuity between commands—state, coordination, or a connection that cannot be represented as durable data—and the ordinary one-shot path cannot meet that requirement. Startup latency alone is not that condition.
