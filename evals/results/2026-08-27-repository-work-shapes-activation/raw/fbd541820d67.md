Ship the one-shot CLI with its startup dependency corrected; do not ship the daemon or bundling yet.

Establish:

- Repeated cold end-to-end timings, separated into process/import, command setup, and remote-operation time.
- An import trace proving the common module pulls in the generator, then compiler, solely to obtain the generated JSON path.
- Behavioural checks that direct JSON loading preserves command grammar, results, safety checks, and readable completed-task records.
- A cold-latency comparison after the change. Measure bundling only if this leaves a material, attributable startup cost.

Test the smallest change first: stop importing the generator from the common runtime module. Resolve/read the already-generated JSON through a dependency-free path (or tiny dependency-free path constant) so the runtime imports neither generator nor compiler.

If that works, remove the daemon prototype and its support burden: HTTP server, service installation, second composition root, duplicate route table, lazy route loader, daemon parity tests, and service status/recovery commands. Keep the original CLI’s validation and command path.

A resident process becomes justified only when an observed, required capability needs live continuity across commands and cannot be represented as durable data—for example, a real long-lived session or in-memory operation with measured value to the operator. A desire to conceal unmeasured startup time is not that condition.
