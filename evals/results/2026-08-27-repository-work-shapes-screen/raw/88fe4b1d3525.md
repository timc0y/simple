Add one daily import job to the existing in-process runner. Let the runner keep scheduling and retrying; the job owns fetching, validating, and applying the customer data.

The import should:

1. Read the agreed source and map each record to the existing customer write path.
2. Validate source data before writing.
3. Upsert by the source’s stable customer identifier, so a retry produces the same result rather than duplicates.
4. Fail transient source or database errors so the runner retries them; reject malformed records as permanent failures with enough context for the application team to correct them.
5. Record the completed source version, timestamp, or equivalent cursor only after all writes succeed, if the source provides one.

This preserves the existing owner of scheduling, retries, and background execution. It does not need a queue, worker service, import framework, or parallel workflow.

Prove it through the runner: scheduled execution imports customers; a transient failure retries successfully; re-running the same input is idempotent; invalid input does not create partial customer records.

The source format, stable identifier, update/deletion rules, and available cursor are not specified. Establish those before implementing the mapping. Reconsider a separate worker only if measured import load or isolation needs exceed the runner’s capability.
