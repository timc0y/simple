Do not ship the daemon.

First establish a cold-process latency breakdown: CLI startup, module import time, generator/compiler import, generated-JSON read, remote operation, and exit. Compare it with the target latency and measure bundling separately before treating it as a solution.

Test one small change first: move the generated JSON path constant into a dependency-free module (or derive it directly), so the command reads the generated JSON without importing the generator or compiler. Prove it with a cold CLI timing and the ordinary command path.

If that removes the meaningful startup cost, delete the daemon, HTTP server, service installation, second composition root, duplicate routes, parity tests, status/recovery commands, and lazy route loader.

A resident process is justified only if measurements after fixing avoidable imports show that cold startup still prevents a real latency or throughput requirement, and its lifecycle, recovery, and operational cost is smaller than that continuing harm.
