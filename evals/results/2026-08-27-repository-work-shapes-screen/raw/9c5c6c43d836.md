Ship the existing one-shot CLI. Do not ship the daemon.

The evidence to establish is:

- Cold-start latency before and after the change, across repeated runs.
- An import/profile trace showing how much time the generator and compiler add.
- Confirmation that the command only needs the generated JSON or path constant.
- Existing command results, safety checks, and durable task records remain unchanged.
- The generated JSON is fresh and has a clear build/source-of-truth path.

Test the smallest change first: replace the runtime import of the generator with a direct import of the generated JSON or constant. Measure that change independently. Bundling is a later experiment only if the import change does not explain or remove the regression.

If the change succeeds, remove the daemon prototype and its supporting machinery: the HTTP server, service installation, second composition root, duplicate route table, lazy route loader, parity tests, service-status commands, and recovery commands. Remove the generator/compiler from the command’s runtime dependency path if no other command requires them.

A resident process becomes justified only when a measured requirement cannot be met by the one-shot command and requires continuity across commands—for example, persistent in-memory state, connection reuse that materially improves a proven workload, or background supervision. That requirement must include a measured benefit large enough to justify the new owner, lifecycle, installation, recovery, and compatibility surface.
