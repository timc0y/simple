Ship the one-shot CLI, with the generated JSON imported directly.

First establish a cold-start latency breakdown: process startup, module loading, generator/compiler loading, remote operation, and output. Verify the generated JSON is current and that direct use preserves command grammar, results, and safety checks. Measure bundling separately before treating it as a solution.

Test one small change first: replace the common module’s generator import with a direct reference to the generated JSON/path constant. The command needs the artifact, not the machinery that produced it.

If that restores the regression, remove the resident daemon prototype and its HTTP server, service installation, second composition root, duplicate routes, lazy loader, parity tests, and service status/recovery commands. Keep one CLI path and durable completed-task records.

A resident process becomes justified only when measurement shows a required capability needs continuity across commands and cannot be represented as durable data—for example, a live owned connection or state whose loss materially prevents the command from working. Startup latency alone is not that condition.
