Design the daily customer import as an in-process job handled by the existing runner.

- Schedule one daily `customer-import` job with the existing scheduler.
- The job fetches the source data, validates and normalizes each record, then upserts customers using a stable external/customer source ID.
- Make the import idempotent: rerunning the same input updates existing records instead of creating duplicates.
- Record a run identifier, start/end time, counts, and failure details for operational visibility.
- Let the runner’s existing retry mechanism handle transient failures; fail clearly on invalid input or unrecoverable errors.
- Verify through the runner that scheduling occurs, imports execute, retries work after a simulated transient failure, and repeated runs do not duplicate customers.

Keep it in-process and avoid adding a separate worker system unless measured load or isolation needs exceed the runner’s capability.
