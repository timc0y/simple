Ship the one-shot CLI with the unnecessary import removed; do not ship the daemon.

First establish a cold-command breakdown: startup/import time, generator/compiler import cost, JSON read time, remote-operation time, and end-to-end latency across fresh processes. Confirm that the generated JSON exists when the command runs and that using it directly preserves command results and safety checks.

Test the smallest change first: have the common module resolve or import the generated JSON’s path without importing the generator. Keep generation as its existing build-time responsibility; the command does not need the generator or compiler at runtime. Compare cold latency and behaviour against the current command. Measure bundling only if that change does not meet the needed result.

If it succeeds, remove the daemon prototype and its HTTP server, service installation, second composition root, duplicate routes, parity tests, status/recovery commands, and lazy route loader. The CLI remains the single command surface and composition path.

A resident process becomes justified only when a measured operator capability requires continuity between commands that cannot be represented as durable completed-task data—for example, a genuinely necessary live session—and the direct CLI cannot meet that requirement after the actual latency cost is attributed and reduced.
