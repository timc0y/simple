Do not ship the resident daemon.

First establish that cold-start import time accounts for the ~180 ms: time process startup, module loading, generated-JSON access, and the remote operation separately across repeated cold runs. Also confirm the generated JSON and existing command grammar/results are unchanged.

Test one small change first: stop importing the generator merely to obtain its path. Point the command directly at the generated JSON via a local path constant (or a dependency-free shared constant only if it has real existing consumers). This keeps the one-shot CLI as the sole composition and execution path.

If direct CLI latency recovers and behaviour matches, remove the daemon prototype and its HTTP server, installation and recovery commands, second composition root, duplicate routes, parity tests, and lazy route loader. Do not bundle unless measurement shows import startup remains the material cost after this change.

A resident process becomes justified only when a measured required capability needs continuity between commands and cannot be represented as durable completed-task data—not merely to conceal uninvestigated startup cost.
