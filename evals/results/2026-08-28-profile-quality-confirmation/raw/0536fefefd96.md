# Simple

## Reality

- This production service has published API clients and retained customer records.
- The API promises the old customer field name for 90 days.
- Old and new clients must both work during that period.
- Operator, scale, failure, and security requirements are unknown.

## Ownership and ordinary paths

- `CustomerSerializer` owns request parsing and response serialization.
- Its alias facility accepts either field name, rejects conflicting values, and emits both names from one internal value.
- Use the migration runner for schema changes.

## Preserve

- Retained customer records.
- The old field name and both client versions for 90 days.
- The transition until 90 days have elapsed and old-field traffic is zero.

## Proof

Verify stored data, both API representations, conflict rejection, rollback, and removal.

## Reconsider

Keep the transition for 90 days and until old-field traffic is zero. Remove the old name only after both conditions hold.
