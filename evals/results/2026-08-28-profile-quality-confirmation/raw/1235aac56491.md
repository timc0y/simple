# Simple

## Reality

- This production service has published API clients and retained customer records.
- The API promises the old customer field name for 90 days.
- Operators, scale, failure, and security facts are unknown.

## Preserve

- Retained customer records.
- Compatibility for old and new clients for 90 days.
- The transition until both 90 days have elapsed and old-field traffic is zero.

## Current boundary

- `CustomerSerializer` owns request parsing and response serialization.
- Its alias facility accepts either field name, rejects conflicting values, and emits both names from one internal value.

## Ordinary paths

- Use the migration runner for schema changes.
- Use `CustomerSerializer` and its alias facility for customer-field compatibility.

## Proof

- Verify stored data, both API representations, conflicting-value rejection, rollback, and removal.

## Reconsider when

- Remove the old field name only after 90 days have elapsed and old-field traffic is zero.
