# Simple

## Reality

- This production service has published API clients and retained customer records.
- The old customer field name is promised for 90 days.
- Old and new clients must both work during that period.
- Operator, scale, failure, and security requirements are unknown.

## Preserve

- Retained customer records.
- The old customer field name for 90 days.
- Old and new clients for 90 days.
- The transition until 90 days have passed and old-field traffic is zero.

## Current boundary

- The service supports old and new clients during the 90-day transition.
- `CustomerSerializer` owns request parsing and response serialization.
- Its alias facility accepts either field name, rejects conflicting values, and emits both names from one internal value.

## Ordinary paths

- Use the migration runner for schema changes.
- Use `CustomerSerializer` for request parsing and response serialization.
- Use its alias facility to accept either name, reject conflicts, and emit both names from one value.

## Proof

Verify:

- Stored data remains intact.
- Both API representations work.
- Conflicting values are rejected.
- Rollback works.
- The old name can be removed safely.

## Reconsider when

Keep the transition for 90 days and until old-field traffic is zero. Remove the old name only after both conditions are met.
