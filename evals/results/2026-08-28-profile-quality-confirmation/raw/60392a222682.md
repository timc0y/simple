# Simple

## Reality

- This production service has published API clients and retained customer records.
- The API promises the old customer field name for 90 days.
- Operators, scale, failure, and security facts are unknown.

## Preserve

- Retained customer records.
- Compatibility for old and new clients during the 90-day transition.
- The old customer field name during that transition.

## Current boundary

- The service currently supports both customer field names.
- `CustomerSerializer` owns request parsing and response serialization.

## Ordinary paths

- Use the migration runner for schema changes.
- Use `CustomerSerializer`’s alias facility to accept either field name, reject conflicting values, and emit both names from one internal value.

## Proof

- Verify stored data, both API representations, conflict rejection, rollback, and removal.

## Reconsider when

- After 90 days have elapsed and old-field traffic is zero, remove the old field name and transition.
