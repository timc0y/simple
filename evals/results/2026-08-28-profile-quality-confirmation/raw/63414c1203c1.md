# Simple

## Reality

- This production service has published API clients and retained customer records.
- The API promises the old customer field name for 90 days; old and new clients must work during that period.
- Operators, scale, failure, and security facts are unknown.

## Current boundary

`CustomerSerializer` owns customer request parsing and response serialization. Its alias facility accepts either field name, rejects conflicting values, and emits both names from one internal value.

## Ordinary paths

- Use the migration runner for schema changes.
- Use `CustomerSerializer` and its alias facility for the field-name transition.

## Preserve

- Retained customer records.
- Both API field names and both client versions for 90 days.
- The transition until 90 days have elapsed and old-field traffic is zero.

## Proof

Verify stored data, both API representations, conflicting-value rejection, rollback, and removal.

## Reconsider when

Remove the old field name only after 90 days have elapsed and old-field traffic is zero.
