# Simple

## Reality

- This production service has published API clients and retained customer records.
- The API must support the old customer field name for 90 days.
- Operators, scale, failure, and security requirements are unknown.

## Required transition

For 90 days, old and new clients must work. Preserve retained customer records, the old field name, and the transition until both conditions hold:

- 90 days have elapsed.
- Traffic using the old field is zero.

## Ownership and ordinary paths

- The migration runner owns schema changes.
- `CustomerSerializer` owns request parsing and response serialization.
- Its alias facility accepts either field name, rejects conflicting values, and emits both names from one internal value.

## Proof

Verify:

- Stored customer data.
- Both API representations.
- Conflicting-value rejection.
- Rollback.
- Old-field removal.

## Reconsideration

After 90 days and zero old-field traffic, remove the old field name and its transition support.
