# Simple

## Reality

This production service has published API clients and retained customer records. The API promises the old customer field name for 90 days. Operators, scale, failure, and security facts are unknown.

## Required compatibility

For 90 days, old and new clients must both work. Preserve retained customer records and the old customer field name. Keep the transition until the 90 days have elapsed and old-field traffic is zero.

## Ownership and paths

Use the migration runner for schema changes. `CustomerSerializer` owns request parsing and response serialization. Its alias facility accepts either field name, rejects conflicting values, and emits both names from one internal value.

## Proof and removal

Verify stored data, both API representations, conflict rejection, rollback, and removal. Remove the old name only after 90 days and zero old-field traffic.
