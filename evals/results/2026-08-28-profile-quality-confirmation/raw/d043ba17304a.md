# Simple

## Reality

- This production service has published API clients and retained customer records.
- The API promises the old customer field name for 90 days, and old and new clients must both work during that period.
- Operators, scale, failure consequences, and security facts are unknown.

## Preserve

- Retained customer records.
- The old customer field name and compatibility with old and new clients for 90 days.
- The transition until 90 days have elapsed and old-field traffic is zero.

## Current boundary

- The service currently supports old and new clients during the 90-day transition.
- `CustomerSerializer` owns request parsing and response serialization.
- Its alias facility accepts either field name, rejects conflicting values, and emits both names from one internal value.

## Ordinary paths

- Use the migration runner for schema changes.
- Use `CustomerSerializer` for request parsing and response serialization.
- Use its alias facility for field-name compatibility and conflict rejection.

## Proof

- Verify retained data, both API representations, conflict rejection, rollback, and old-name removal.

## Reconsider when

- After 90 days have elapsed and old-field traffic is zero, remove the old name and end the transition.
