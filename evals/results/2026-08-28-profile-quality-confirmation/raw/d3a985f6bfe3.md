# Simple

## Facts

- This production service has published API clients and retained customer records.
- The API promises the old customer field name for 90 days.
- Old and new clients must work during that period.
- Operator, scale, failure, and security facts are unknown.

## Ownership and path

- Use the migration runner for schema changes.
- `CustomerSerializer` owns request parsing and response serialization.
- Its alias facility accepts either field name, rejects conflicting values, and emits both names from one internal value.

## Required outcome

- Preserve retained customer records and both API field names.
- Keep the transition until 90 days have passed and old-field traffic is zero.
- Then remove the old field name.

## Proof

- Verify stored data, both API representations, conflict rejection, rollback, and removal.
