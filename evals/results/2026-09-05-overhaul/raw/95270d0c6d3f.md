The domain has three lookup outcomes:

- **Absent:** no database row exists; the account has never existed.
- **Active:** a row exists and `expires_at` has not passed.
- **Expired:** a row exists, but `expires_at` is in the past.

The smallest handling rule is: check whether a row exists first; only then evaluate its expiry. Return distinct domain outcomes from the profile service.

Both cases must not become `null`:

- Missing account → caller observes “account not found” / never-created message.
- Expired account → caller observes “account expired” message.

Callers should use the service’s outcome, not infer the reason from the current time.
