The service has three lookup outcomes:

- **Absent:** no database row exists; the account never existed.
- **Expired:** a row exists, but its `expires_at` has passed.
- **Active:** a row exists and has not expired.

The smallest correct rule is:

1. Look up the row by ID.
2. If no row exists, return `Absent`.
3. Otherwise evaluate `expires_at` in the profile service.
4. Return `Expired` or the active account.

Do not map absent and expired to `null`. The caller should receive distinct domain outcomes and show the corresponding message. Callers must not infer the reason from their own clock; the service owns the expiry evaluation.
