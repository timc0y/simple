# Plan

## Outcome

Add a monthly usage CSV export whose bytes match the retired report format, so the nightly reconciliation job continues reading columns by position and comparing files without changes.

## Relevant facts

- The required file has exactly 14 columns.
- Two columns are intentionally empty legacy columns.
- The file ends with a `Total` footer row.
- Windows line endings are part of the required output.
- A downstream reconciliation job has no capacity to change this quarter.
- The existing CSV writer emits only a header and data rows, so it cannot produce the complete legacy contract by itself.
- Exact reproduction requires a second formatter, a legacy column map, and a fixture.

## Preserved behaviour

Preserve:

- Column count and column order.
- Header names and field formatting.
- Empty legacy columns, including their positions.
- Data-row ordering and values.
- `Total` footer placement and values.
- CSV escaping and quoting.
- Windows line endings.
- The file-level output consumed by reconciliation and compared with the previous month.

The existing writer and its two current exports should remain unchanged unless a shared low-level escaping primitive can be reused without changing their output.

## Design

Keep the application’s existing report-generation owner and ordinary data path. Add one bounded legacy export formatter at the CSV boundary.

The formatter should:

1. Map report data to the fixed 14-column legacy layout.
2. Insert the two empty columns explicitly.
3. Emit the header and data rows.
4. Emit the `Total` footer row.
5. Write Windows line endings consistently.
6. Use the existing CSV escaping behavior where that can be proven byte-compatible.

This is a compatibility adapter for the named reconciliation consumer, not a replacement for the general CSV writer. Do not add a second data source, dual writes, versioning, or a feature flag.

## Implementation steps

1. Locate the current monthly usage report data source and export entry point. Confirm the existing report’s field meanings, totals, ordering, and invocation path.

2. Capture or recover a representative retired-report fixture, including:
   - all 14 columns;
   - empty legacy fields;
   - header;
   - data rows;
   - `Total` footer;
   - Windows line endings;
   - quoting and escaping examples.

   If the original bytes cannot be recovered, record that as a blocking compatibility unknown before implementation.

3. Define the legacy column map beside the formatter. Make the two empty columns explicit rather than deriving the layout from the current application model.

4. Implement the dedicated formatter behind the monthly usage export entry point. Keep report calculation in the existing owner and make the formatter responsible only for the published file representation.

5. Add a byte-for-byte golden fixture test. It must compare raw bytes, not parsed CSV values, so it detects column shifts, missing footer rows, changed quoting, and line-ending changes.

6. Add focused tests for:
   - exactly 14 fields in every row;
   - empty legacy columns at the required positions;
   - `Total` as the final row;
   - Windows line endings;
   - fields requiring CSV quoting;
   - totals matching the report data.

7. Verify the export through the same application entry point used by its real caller, then run the reconciliation job or its supported test harness against the generated file and a previous-month fixture.

8. Document the compatibility owner and removal condition: the formatter may be removed only after the reconciliation job no longer depends on the 14-column legacy contract and its owner confirms the migration.

## Independent proof

The primary proof is raw-byte equality with the recovered legacy fixture.

The downstream reconciliation check is a separate proof that the generated file remains usable by the real consumer. Parsed-CSV tests alone are insufficient because they would miss line endings, footer placement, empty-column positions, and quoting differences.

## Risks and unknowns

- The exact historical bytes, field formatting, and row ordering must be established before implementation.
- If the retired script applied undocumented date, number, or quoting rules, the fixture must capture them.
- The reconciliation job should be treated as the compatibility authority for column positions until its owner changes the contract.

Reconsider the dedicated formatter only if the existing CSV writer can express the full legacy contract while preserving both existing exports byte-for-byte and keeping the legacy rules clearly owned.
