# Plan

   - Fixed 14-column order.
   - Preserve both empty legacy columns.
   - Include the `Total` footer row.
   - Use Windows (`CRLF`) line endings.
   - Match the retired report’s quoting, escaping, date, number, and blank-value formatting.

2. Add a dedicated legacy formatter for the monthly usage report instead of using the existing CSV writer, since that writer omits the footer and does not represent the legacy layout.

3. Add an explicit legacy column map so fields are emitted by the required positional order, including the two empty columns.

4. Add a fixture containing a representative old report, including:
   - Header row.
   - Data rows.
   - Empty legacy columns.
   - `Total` footer.
   - Windows line endings.

5. Implement byte-for-byte golden-file tests comparing the new export with the fixture.

6. Add focused tests for:
   - Exactly 14 columns on every row.
   - Correct placement of the empty columns.
   - Correct `Total` footer values and position.
   - `CRLF` line endings.
   - CSV quoting and escaping for commas, quotes, and newlines.
   - Empty and missing values.

7. Add an integration test covering the monthly usage report export and verify that the generated file uses the legacy formatter.

8. Document that the legacy format and column positions are compatibility requirements because the external reconciliation job cannot be updated this quarter.

9. Validate the export against a prior month’s file before release, checking both byte-level compatibility and the reconciliation job’s expected column positions.
