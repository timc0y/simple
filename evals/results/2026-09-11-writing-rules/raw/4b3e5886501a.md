# Plan

## Outcome

Add the monthly usage report export without breaking the consumer's spreadsheet import.

The facts support preserving the report’s 14 column names and ordering where the consumer depends on them. They do not support preserving the retired file byte for byte.

## Decision

Treat “identical” as schema-compatible:

- Keep the existing 14-column layout, including the two empty legacy columns.
- Preserve the column headers the consumer imports by name.
- Use the application’s existing CSV writer.
- Do not reproduce the `Total` footer or Windows line endings unless the consumer confirms they are required.

A byte-for-byte legacy format would require a second formatter, a legacy column map, and a fixture, but no current consumer or contract needs that complexity.

## Implementation steps

1. Trace the two existing CSV exports and identify their shared writer and invocation path.
2. Add the monthly usage report to that existing export owner.
3. Define the report’s header order to match the retired report, including the two empty legacy columns.
4. Map monthly usage data into those columns, leaving the legacy columns empty.
5. Confirm that the writer’s normal header-and-data-row output is accepted by the consumer's header-based import.
6. Add focused tests for:
   - exact header names and order;
   - the two empty legacy columns;
   - representative monthly data;
   - absence of accidental column shifts.

Do not add a footer, Windows line-ending conversion, or a byte-level fixture in this implementation.

## Proof

Verify the generated CSV through the public export path and import it into a representative the consumer spreadsheet. The check must confirm that headers select the intended columns and that values remain aligned.

A test comparing the complete file bytes would encode an unsupported compatibility promise.

## Risk and reconsideration

The remaining risk is that the consumer relies on an undocumented footer or line-ending behaviour despite its stated header-based import.

Reconsider byte-for-byte compatibility only if the consumer reports an import failure or identifies a consumer, retained workflow, or support commitment that depends on the footer, empty-column representation, line endings, or exact file bytes.
