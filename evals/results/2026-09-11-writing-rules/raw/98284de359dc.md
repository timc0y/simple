# Plan

## Outcome

Add the monthly usage report through the existing CSV writer. Preserve the column headers and values that finance imports, but do not reproduce the retired file byte for byte.

The old line endings, footer row, and two empty legacy columns are not compatibility requirements: finance imports by header name, does not compare monthly files, and no API, job, or retained data depends on the file bytes.

## Steps

1. Confirm the finance import contract from the retired report:
   - Keep every consumed column header unchanged.
   - Keep each column’s value and meaning unchanged.
   - Exclude the two empty legacy columns unless finance identifies them as required headers.

2. Build the monthly usage export on the existing CSV writer. Reuse its header and data-row behavior instead of adding a second formatter.

3. Omit the retired `Total` footer and Windows-specific line endings. The current writer’s standard output is sufficient because neither is part of the consumer contract.

4. Add a fixture covering:
   - The required headers.
   - Representative monthly usage rows.
   - Header-based column mapping.
   - Absence of accidental extra columns or footer data.

## Proof

Verify that a finance-style import selects the same fields by header name and produces the same usage values as the retired report. Do not assert byte equality, legacy empty columns, footer presence, or line-ending style.

## Reconsideration condition

If finance’s import requires the empty columns, footer, or Windows line endings after all, document that as an explicit compatibility requirement and add only the required behavior to the existing writer path.
