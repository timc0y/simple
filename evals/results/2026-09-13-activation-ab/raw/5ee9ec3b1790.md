Six weeks of API failure proves the current priority is wrong, but not that the API has no obligation. The deciding evidence is:

- CSV freshness, completeness, and correctness versus the API’s intended contract.
- Whether the API failure is a fixable configuration/outage issue or a permanently unavailable vendor service.
- Whether the vendor API is the authoritative source or required for updates, reconciliation, or compliance.
- Whether the CSV cache has a reliable producer, retention policy, and staleness monitoring.
- Whether any consumers depend on API-specific fields or behavior.

Delete the API only if the vendor contract is ended or the API is definitively unavailable, no consumer requires it, and the CSV fully satisfies the data contract. Keep the current order only if the API remains authoritative and the CSV is demonstrably stale or incomplete. The six-week failure history alone supports swapping, not deletion.
