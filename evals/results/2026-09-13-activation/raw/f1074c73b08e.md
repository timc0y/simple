The six-week failure record proves the current priority is wrong, but not that the API can be deleted. Deletion requires evidence that:

- the CSV is complete, correct, and fresh enough for every consumer;
- its cache has a defined owner, retention, and recovery process;
- no contract or operator workflow requires live vendor API access;
- the API failure is either permanent or no longer worth recovering;
- an end-to-end test proves CSV-only imports work and alert when the cache is stale or invalid.

Keep the API only if it provides a required capability the CSV cannot—especially freshness, missing records, or recovery when the cache is absent. Otherwise, after an explicit deprecation period with no such need, delete it rather than preserving a permanently dead path.
