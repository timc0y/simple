# Human-understanding initial screen

Registered before model answers. The owner explicitly requested the two approved final-answer and visual-purpose instruction changes. This is a single-repeat initial screen; adoption is independent of a gain. No improvement, superiority, human comprehension, native-hook execution or live UI claim is permitted from it.

The frozen baseline is the skill immediately before those two edits. The candidate changes only SKILL.md and references/writing.md. Each solver reads its assigned complete skill condition. All other files, prompts, harness, tools, requested gpt-5.6-luna model, medium reasoning and isolation are equal. Codex code_mode_host is enabled, native hooks disabled, implicit system-skill discovery disabled, user configuration ignored and the Simple operator path points to a missing fixture file. An external sandbox denies repository, global skill, plugin, memory and operator reads. No install or user-config mutation is permitted.

Budget: 12 sequential model calls, eight cells, one repeat each. Dataset-explanation and owner-cleanup each compare baseline/candidate with a seed exec and actual exec/resume follow-up (eight calls). Both arms receive identical old Stop feedback; the treatment is only the two skill edits. Simple-status and varying-input compare both arms with one exec (four calls). Reverse condition order on alternating cases. Stop and retain evidence on process/setup failure; no retries or extension. Previous native hook failures remain untouched and native lifecycle plumbing is not reattempted.

Judge only the final last-message artifact, not an earlier useful answer. Continuation cases retain their existing synthetic fixture and checks. Simple-status catches unnecessary output and generated files. Varying-input accepts correct formula, table, threshold or a working local interactive form; HTML is not compulsory. Motion is unjustified when only the order of ordinary steps matters. All forms must preserve decisive evidence and the unmeasured item-time limit. Manual final-only decision review accepts equivalent explanations and records uncertainty; automated word checks are only screening flags.

Final-only decision questions: Which dataset should be tried first and why? What is still unknown? Has the local source been changed and checked? Is the search fix usable by the user yet, and what remains? Does the review fit at the stated assumption, which inputs can change that answer, and which fact remains unmeasured? The grader criteria, pass/fail references and artifact-mutation checks are frozen before solvers. A known-pass and targeted-fail check is required for every case. Run npm run test:behavior before executable model evaluation. Keep all grader material outside solver workspaces.

Retain exact frozen hashes, commands, prompts, raw JSONL, stderr warnings, thread identifiers, last answers, timestamps, usage, latency, seed and final file snapshots, artifact checks and manual review. Redact private machine traces explicitly in public evidence; originals remain private. Model revision is recorded if exposed, otherwise marked unavailable. A paired baseline-pass/candidate-fail result requires individual review and cannot be hidden by aggregate scores. Do not change the grader after seeing answers or rerun away a failure.
