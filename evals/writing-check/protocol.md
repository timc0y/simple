## Development cases

The ordinary case format is reused, with all authoritative text inside `prompt.md`:

| Case | Failure or counterexample |
| --- | --- |
| `writing-paraphrase-roles` | Faithful new wording versus retained names/numbers with swapped responsibility |
| `writing-conditions` | Missing condition, possibility made promise and approval mistaken for success |
| `writing-punctuation-only` | Exact word/order boundary versus a rewrite |
| `writing-leave-good` | Already-good writing that should remain unchanged |
| `writing-requested-improvement` | Faithful unchanged copy that does not make the requested edit |
| `writing-correction-scope` | A previous factual correction must not become a universal style rule |
| `writing-long-exception` | Long-range exception, code, quotation and citation attachment |
| `writing-unknown` | Unknown cause and timing must remain unknown |

These lead-authored cases are development fixtures, not held-out performance evidence.
Pass/fail references are examples, not mandatory wording, except for explicit exact
requirements. The case's requested artifact takes precedence over a generic prose
shape. Neither references nor semantic criteria have been validated by a new model
grader in this change.

Communicator separately tests approved-example replacement, exact forgetting,
compose/review context, and lexical-clean meaning failures through its own runtime.
There is no runtime import between the repositories.

## Bounded forward tasks

After selecting the final instructions, an independent helper supplies one synthetic
handoff task and one synthetic email task. Each may use at most two collaboration
turns: one draft and, only if the ordinary review identifies a defect, one targeted
repair. No retries or additional candidates. Stop at that bound and retain failures.
Use Luna for the Simple task as required by this repository. Record the requested
model identifier and any unexposed revision rather than inventing an exact model.
The collaborator service is the host; do not call it a Codex/Claude installed-plugin
test. These tasks are non-comparative smoke checks, not a matched experiment.

Record exact task inputs, final instruction hashes, outputs and the lead's acceptance
review in the result owner. Keep detailed private traces out of public artifacts.
Do not infer zero token consumption from the zero paid-API budget; usage not exposed
by the collaborator service remains unknown.

## Deterministic instrument checks

`npm test` checks frozen source delivery, exact identifier sets, real Boolean verdicts,
integer rubric scores, malformed/missing/duplicate results and stable input mapping.
Both-pass and both-fail judgments remain possible. Optional supplied swapped-order
verdicts retain both records and an order-check result; disagreement is inconclusive,
not a preference win or a genuine tie.

Run the repository-required profile, skill-validator and whitespace checks. A local
source test cannot establish the installed skill's version or host delivery. The
native isolated Luna runner uses macOS `sandbox-exec`; its real model path is not
verified on this Linux executor.
